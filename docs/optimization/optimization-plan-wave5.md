## 0. 为什么要再来一波

你点名「比之前 Grok 那轮更好」。GroK 式的**流程优化**（更钝、更可验证、通路稳）已经吃了一轮红利；  
下一层差距通常在：**研究输入的证据链、组合层面的归因、以及「拥挤≠见顶」的判据质量**。

业界两个方向值得抄作业：

1. **LLM 研究管线**（ThesisLoop / Hubble 等）：从一次性 prompt 走向 **确定性管道 + 结构化引用 + 矛盾/陈旧检查 + 回放/归因**；因子/信号侧强调 **crowding、family 多样性、IC/双指标、持久诊断**。  
2. **A 股中长线机构框架**：三重交叉（**结构/板块轮动**、**技术/阶段**、**宏观业绩-流动性-估值**）；**盈利修正连续性**、**景气拐点（如 ROE_TTM）**比单纯拥挤度更接近顶部信号；数据下沉到**订单、产能利用率、资本开支**等中观指标。

## 3.1 代码级缺口摘要（来自只读审查）

已确认、**建议在 W5 内消化**的工程问题（按严重度）：

1. `ak_direct` 绕过代理是**进程级全局状态 + monkey-patch**，与 8 线程均额抓取存在竞态。  
2. `_enrich_amount_avg` 的 25s「超时」杀不掉已挂起的 akshare 调用（无显式 timeout）。  
3. `sector_link` 在门禁翻动作**之前**生成 → 「research buy → buy」可出现在终局 watch 上。  
4. `finish=length` 只记日志，无显式检测与「压缩 payload + 升 budget」重试。  
5. `Path("data/cache")` 随 CWD 漂移；板块映射靠子串；`new_credit` 排序与社融不一致。  

对应任务：W5-C5 ~ W5-C12。

## 3. 与报告形态的增量（用户侧可见）
